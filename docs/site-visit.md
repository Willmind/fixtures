# 毛坯实景导览

## 来源与对应

资料来自用户提供的 `实拍图片-毛坯` 文件夹：24 张 HEIC 照片和一段约 43 秒 MOV 走拍。2026-10-04 整理入站；这个日期是整理日期，不冒充拍摄日期。房间归属沿用用户的文件夹名称，再关联现有户型图和模型的房间 ID。

| 实拍分组           | 房间 ID | 照片数 |
| ------------------ | ------- | ------ |
| 客餐厅、餐厅、门口 | living  | 5      |
| 主卧               | master  | 3      |
| 次卧a              | parents | 2      |
| 次卧b              | study   | 2      |
| 客房               | guest   | 2      |
| 厨房               | kitchen | 3      |
| 公卫               | bath    | 2      |
| 主卫               | ensuite | 1      |
| 主阳台             | balcony | 2      |
| 生活阳台           | utility | 2      |

`parents`、`study` 是历史代码 ID；界面仍称次卧 A、次卧 B，并不代表最终用途。客餐厅照片中同时包含入户和餐厅，暂不拆出无独立模型边界的房间。

`src/visit/photos.json` 保存来源相对路径、房间关系、画面说明和网页图片尺寸。图片尺寸是像素，不是房屋实测尺寸。`src/visit/content.ts` 分开维护现场可见信息与待测事项，不能从白色墙面推断具体涂层，从管线外观推断用途，或从照片推断承重性质。

## 展示与加载

- 首页房间详情可打开该房间实拍；实拍页提供同一房间的平面位置、三维位置和相关 PDF 图纸。
- URL 的 `view`、`tab`、`room` 保存浏览位置，刷新与浏览器返回可以恢复。三维内重新选房间时也同步 URL。
- 当前大图按需加载；缩略图懒加载。照片提供加载提示、失败重试及原比例放大阅读，放大框支持方向键和 Escape。
- 视频只有在用户点击播放或片段后才绑定 MP4 地址；使用原生播放器，支持手机内联播放。片段时间是人工按画面整理的导航点，不是测绘轨迹，也不覆盖每个房间的全部角度。

## 网页副本

原件不移动、不修改，不放入 Git。`public/site-visit/` 是随静态站点发布的网页副本，约 9.5 MB（十进制），其中视频约 6.5 MB。仍使用现有腾讯云 Nginx 和自动发布流程，无新增服务或付费存储。

- 照片：正确旋转，长边最大 1800 px WebP；缩略图长边最大 520 px。去除 EXIF/GPS。
- 视频：720 × 1280、24 fps、H.264/yuv420p、约 43 秒，无声。原片是 Dolby Vision 8.4 / HLG；使用 `scripts/export-site-video.swift` 调用 AVFoundation 的 H.264 导出预设，先由 macOS 原生转换为 SDR BT.709，再由 FFmpeg 降帧率、压缩及去除元数据，不再添加明暗映射或曝光滤镜。旧版 `zscale + Mobius`（包括 `npl=203` 的修订）在同一时间点的室内墙面、地面上仍明显偏亮，已替换。原片不修改；SDR 仍不能保证与每块 HDR 屏幕显示完全一致。`moov` 位于媒体内容之前，可边下载边播放。
- 转换方式依据 [Apple 的 HDR / Dolby Vision 转换说明](https://developer.apple.com/av-foundation/Incorporating-HDR-video-with-Dolby-Vision-into-your-apps.pdf)。更新视频时同步生成封面，并修改 `Walkthrough.tsx` 中视频与封面的资源版本号，避免沿用旧缓存。
- 整理脚本：`scripts/prepare-site-visit.py`。需要 macOS 15+、Swift 命令行工具、`sips`、Pillow（仅处理照片时需要）和包含 `libx264`、`libwebp` 的 FFmpeg。原生图像、视频转换必须能访问 macOS 媒体服务；受限环境可能导致导出失败或 HEIC 全黑，脚本会报错而不覆盖已有视频。构建及服务器均无需这些工具。

```sh
python3 scripts/prepare-site-visit.py '/原件目录/实拍图片-毛坯' --ffmpeg /path/to/ffmpeg
# 单独更新视频，不重做照片
python3 scripts/prepare-site-visit.py '/原件目录/实拍图片-毛坯' --ffmpeg /path/to/ffmpeg --video-only
```

## 三维调整边界

继续使用 React + Three.js。照片用于校正白色室内墙面、灰色厨卫墙面、深色窗框，以及两个阳台的玻璃栏板。墙面材质按现有墙段示意，未精分共用墙两侧；栏杆高度、立柱间距、窗框分格仍为示意。

没有从照片臆测窗台进深、实际净高、墙厚或排水尺寸，也没有声称完成照片自动建模。现有几何继续依据 PDF 人工重建。下一次应补测窗台、门窗洞、层高和各房间净尺寸，再修改 `src/model/plan.ts`。精细窗台、门框、设备等几何复杂到不适合代码维护时，可用 Blender 制作 GLB 局部构件，再在 Three.js 中加载。

2026-10-04 用户补充确认：主阳台、生活阳台均有顶板，厨房与生活阳台之间没有门，洗衣机和热水器放在生活阳台靠厨房侧。模型已补顶板并移除误画的门洞，保留厨房的餐厅侧入口。半高墙及俯视下顶板半透明，避免遮挡内部。顶板厚度、高度和设备体量为示意；热水器机型、安装高度及是否与洗衣机上下布置尚未确定。

客厅只比较两种用户提出的候选朝向：电视 / 电视柜靠客房、沙发靠次卧 A，或两者对调。`src/model/arrangements.ts` 保存位置与示意体量，`HomeFixtures.ts` 创建可切换的三维对象；没有将默认预览的方案一写入「已定案」或房间笔记。家具与设备点选仍返回对应房间，隐藏的候选对象不参与点选。

同日用户补充：两个阳台都各有「保持原样 / 封窗」两种候选，并进一步指定整面落地玻璃。三维默认保持原样，两个选项独立控制；落地玻璃从地面通至顶板，每个外侧面只留周边细框，预览中隐藏原栏杆，切回原样后恢复。不封住通往室内的门窗，也不改变厨房侧实墙。窗框与开启方式尚未定案。预览选择仅保留在当前模型页面，不写入已确认现状。

生活阳台靠餐厅一侧：`public/site-visit/dining-01.webp` 实拍可见落地推拉玻璃门及两侧墙体。当前三维按用户随后明确提出的敞开效果展示，移除这一整段分隔墙、玻璃门窗及两侧墙垛；照片保留原貌。阳台外侧栏杆/落地玻璃、顶板、厨房侧墙及设备位置不受这项方案调整影响。

## 验证

`scripts/site-visit.test.mjs` 检查房间与照片覆盖、素材有效签名和大小、MP4 快速开始结构、片段范围、导航链接往返与无效参数回退。运行 `npm test`、`npm run build`，并在浏览器检查桌面/手机、照片翻页与关闭、三维联动、原图返回、视频播放和片段跳转。
